# CP-8 — actual prior/current deliverable comparison

Compare the two complete pinned TDG publication bundles supplied as prior/* and
current/*. The current user supersedes the imported decision post-mortem task:
compare deliverables, not a past investment decision, calibration or approval gate.
This is the same historical annual accounting base, not a new reporting period or
evidence of changed issuer conditions. Execution is November 5, 2026. Preserve
financial dates, subsequent events, source limitations and each run's scope.

Use list_sources and actual read/search tools. Read both delivery receipts,
report-view.json, calculation.json and relevant view/Model records and original
handoffs. Inspect the actual rendered report/model HTML sufficiently to check
their destinations and bindings. Source JSON/HTML text is not a visual browser
check. All complete files are supplied; tool pages are 12,000-character chunks,
not physical pages. Use precise file, chunk and field/heading locators. Retain
exact prior/current receipt hashes, run IDs and relevant artifact hashes. Do not
claim complete exhaustive record comparison unless actually performed.

Use six H2 headings: Request, Sources, Findings, Calculations, Gaps, Next module.
Under Findings provide exactly one table with headers:
Dimension | Prior deliverable | Current deliverable | Explanation
and exactly these seven rows, once each: Values; Periods; Assumptions;
Conclusions; Sources; Limitations; Output scope. Each row must contain concrete
located observations on both sides and explain whether a difference is a source
change, correction, analytical judgment, presentation/scope expansion, or
unresolved. These are report selectors, not a substitute for substantive analysis.

Compare important annual amounts and definitions (ordinary and As Defined EBITDA,
cash, debt, cash flow, margin/leverage calculations), missing versus zero,
quantity/units, fiscal dates, legal reach, assumptions, qualifications, committee
conclusions, sources, unresolved contradictions and actual published outputs.
Trace material numerical differences to original handoffs and calculation
lineage. Do not silently choose conflicting source values or regenerate analysis.
The Model is delivery consumption of actual handoffs, not a separate analyst run.
Determine the actual panel/chart/Model/JSON scope from the bundles. A newly added
legal or committee module does not mean the issuer changed. An unavailable
prior-run decision is not an adverse change. A handoff's provisional remarks
must not override the actual completion/publication evidence supplied.

Retain a concise changed/unchanged/unresolved register, source coverage and
material implications for readers. Distinguish historical function proof from
current underwriting, native analytical-contract acceptance and independent
visual assurance. No current recommendation, new forecast, imported missing
input approval gate, Excel requirement, CP-MEMO or second analytical execution.
Use calculate only for genuinely needed new arithmetic, preserving operands and
definitions; do not invent deltas for incomparable quantities. Call write_handoff
and repair only justified issues via edit_handoff. Actual response is retained
and the existing delivery process consumes it into a comparison report.
