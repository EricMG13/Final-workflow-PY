# CP-8 — compare selected prior/current TDG deliverables through CP-OS

Current user definition: compare deliverables from prior runs with the latest
selected current run across values, periods, assumptions, conclusions, sources,
limitations and output scope. The legacy investment-decision post-mortem and
three-decision gate are superseded. No investment history or later return is
required. No fresh issuer analysis or financial forecast is requested.

The actual CP-OS request supplies complete, receipt/hash-checked prior/current
bundles as source bytes. Prior is the TDG five-section fresh-host CP-2 report;
current is the subsequent TDG five-section plus HTML Model/chart/JSON publication.
Both financial bases are30 September2024. "Latest" means this explicitly selected
local TDG publication, not current2026 issuer information. Another issuer's
subsequent report is outside this comparison.

Read both reports, their View/ReportView files, copied analytical handoffs and
all additional current Model/source/calculation files. Use exact retained source
identities. Compare semantic facts/definitions, not merely row indexes, byte
counts, citation numbering or added filenames. Prior absence of a published
measure is not zero, and a newly displayed amount is not financial growth.

Compare all five narrative sections and the new Model/three charts. Identify
which facts, assumptions, conclusions and restrictions are unchanged, newly
visible, revised, missing or unresolved. Keep money, shares/per-share, ratios,
source dates, annual/interim windows, and conditional scenarios distinct.
Do not treat publication of raw quarter/forecast tables as a new CP-2 synthesis
or verified current forecast. New delivery coverage does not close unrelated
credit evidence gaps or create native accepted heads.

Write the six common H2 headings. In Findings, include exactly one table headed
`Dimension` with one row for each of: Values, Periods, Assumptions, Conclusions,
Sources, Limitations, Output scope. Explain prior/current content and material
effect with concrete artifact/table/cell or handoff references. Additional
evidence/gap tables are permitted. Explain any presentation-only change and
the strongest contrary reading. Give targeted repairs only when evidence
demonstrates a problem; do not manufacture a repair to make the loop active.

Calculations states the actual comparisons performed; no new ratios, returns,
probabilities or issuer-financial calculations. Gaps retains all incomparable
or unverified scope. Next module instructs separate delivery to consume this
actual comparison without rerunning upstream analysis. No Excel output,
subagent, provider call, credential file, historical mutation or new controller.

This is an actual current-host-model exchange with preceding context and access
to pre-output check data; it is not blind, independent-context or provider/native
qualification. Acceptance requires instruction/source comparison plus actual
downstream publication and checks. Markdown/table shape alone is not analytical
approval. CP-OS owns retain, bounded repair, resume and checked completion.
